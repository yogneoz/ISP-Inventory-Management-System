## Goal

READ-1 deleted the orphaned client limb of the bounded
`GET /api/customer-devices` array but deliberately kept the server route: an
older deployed bundle might still call it, and deleting a live endpoint is a
deployment decision. Round 6 was the deferred second half of that item. CDR-1
removes the route, its handler and its 2,000-row query once nothing in the
bundle can reach it, and pins the retirement with a 404 and a source guard so a
re-registration has to be deliberate. That closes the read path's last legacy
device read — the one endpoint that answered “all devices” with a page-sized
array that looked complete, which is the exact trap the client half had closed.

One small item, no migration, no new screen.

## The deployment fact, recorded

The condition READ-1 attached was “once no older deployed bundle can be calling
it”. The repo cannot prove the deployment fact, so the item recorded what it
assumed: client and server are built and served from one deploy
(`npm run build` → `dist/`, served by the same process), so the only caller the
route still served was a browser tab holding a cached pre-EXCH-1 bundle against
an updated server — a tab whose Device Exchange read answers 404 until reload,
while every current screen is unaffected. The alternative was keeping a
whole-table-style read alive indefinitely for a tab already running code nobody
supports. Full reasoning in
[CDR-1](2026-10-27-round-6/CDR-1.md#the-deployment-fact-recorded).

## Boundary kept

`GET /api/bootstrap/local?key=customerDevices` still answers an older bundle —
unbounded, because `fetchBootstrapSlice` applies no limit for that key — and the
same `BOOTSTRAP_TABLES` mapping feeds the operational cache, so retiring it
needs the cache mapping separated from the slice mapping. It is now the only
legacy whole-table device read; it stays recorded here and in the archived item
note as the round's follow-up, not folded into the item.
