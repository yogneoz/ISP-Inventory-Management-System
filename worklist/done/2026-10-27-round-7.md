## Goal

CDR-1 retired the bounded bare-array `GET /api/customer-devices` route and
recorded its one follow-up: `GET /api/bootstrap/local?key=customerDevices`
still answered a device request with the whole `customer_device_records` table
for a cached pre-VOL-4b bundle. The blocker was the shared mapping — the same
`BOOTSTRAP_TABLES` entry fed the slice endpoint and the operational cache
(`CACHE_LOADS`), and the cache still needs it. Round 7 splits the mapping: the
cache keeps its load, the slice surface loses the key, and the retired key
answers definitively instead of a transient 503. That closes the last legacy
device read — no path in the repo answers a device request with a whole table
any more.

One small item, no migration, no new screen.

## The measurement, and the branch probe

Measured through the real mapping before the change (scratch rows in the real
table shape, insert + read in one rolled-back transaction): 12,000 rows were
**5,414.2 KiB raw / 431.5 KiB gzip** (462.0 B / 36.8 B per row), so the 10×
model is **52.87 MiB / 4.21 MiB** — the slice had been serving the removed
national array all along, one request per stale bundle. The same probe settled
the second reason to retire it: the `/api/bootstrap/local` branch guard covers
`/bootstrap`, not the slice endpoint, so a branch account that omitted
`branchId` read all 12,000 rows across both branches, where the paged route
refuses that request with 403 (a forged branch was refused here too — only the
omission slipped through). Retirement removes the device case entirely; the
guard gap itself is recorded, not generalised. The demo DB holds 0 device rows
and the scratch rows were deleted after the run (leftover = 0), so the size
model is the recorded VOL-4b one.

## Boundary kept

The `customers` slice stays for the same older-bundle reason, and its mapping
is shared with the cache the same way — retiring it would need the same split
first. The paged device reads, the exchange lifecycle and the serial register
are untouched. Both boundaries are recorded as the inputs a future round would
start from, not folded in.
