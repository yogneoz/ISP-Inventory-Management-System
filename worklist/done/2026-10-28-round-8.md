## Goal

Round 7 closed the payload work, so this round asked the next question: are
there loops the static structure hides? A whole-tree sweep covered timers and
their cleanup, explicit loops, React effect-dependency cycles, listener and
subscription symmetry, circular imports, retry paths, swallowed errors and
server→client feedback loops (method and dismissed sets in the audit doc). It
found three real defects, two hardening items, and one API gap the UI cap had
left open.

## Why the audit items were not “notes”

AUD-1/2/3 each needed a behavioural test, not a source guard alone: the
in-progress-count merge, a COMMIT that fails after a successful write, and the
clamp at every entry point. QTY-1 then closed the other half — the API accepted
what the UI refused — and its eight handlers share one rule with the browser
(`shared/lineQuantity.ts`), which is why the screen and the endpoint cannot
drift. AUD-4 and AUD-5 were the two hardening items the audit recorded as
unguarded; the close pass fixed both rather than carrying them as open debt,
because each is a small invariant with a direct regression test
(`tests/syncRetryGuard.test.ts`, `tests/bsRangeSpan.test.ts`).
